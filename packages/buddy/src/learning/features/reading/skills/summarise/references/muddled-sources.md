# Muddled Sources

Use this when the source itself is the problem: a rambling essay, meeting or lecture notes, a long chat thread, the learner's own notes, a report that lists findings without a point, or prose too dense to follow. The aim is still one main point with a clean Key Line; you build it from the bottom up instead of finding it at the top.

# Take The Text As Given
Treat the source as a closed universe. Work only with what it says, set aside whether its claims are true, and aim only at making its message plain. A muddled text is usually muddled in the order of its ideas, not in its sentences; putting the same points in a clear order, main point first, often makes it readable with little rewording. Judge the content afterwards, separately and labelled, if the learner needs that.

# Sort From The Bottom Up
1. **List the points.** Write each point the source makes as one short plain sentence, with its location. Merge points that say the same thing.
2. **Start with the action ideas.** Pick out the decisions, recommendations, instructions, and open to-dos first. They are easier to pin down than statements about how things are, and the rest often turns out to be the case for them.
3. **Relate the points.** Mark which points cause or lead to which, and which are alike. Sketch the cause-and-effect links as boxes and arrows; separate lines of reasoning show up as separate strands, and so do gaps where a link the argument needs is never stated.
4. **Draw conclusions.** Group the related points and state what each group adds up to (see summary-statements.md). Those statements are candidates for the Key Line.
5. **Choose the main point.** Of the conclusions you could put on top, take the one that answers the question the source's audience actually has (see the next section).

For a chat thread, the action ideas are usually what was decided and what was left to do; the situation ideas are what was found or reported. A useful main point is often what the thread settled, or that it settled nothing and why. Attribute points to the people who made them.

# Work Backward To The Question
When the source never says what question it answers, reconstruct it. The author wants the reader to know these points; the only reason a reader should know them is that they settle some question; that question grew out of the reader's circumstances. Trace back along that line: from the points, to the question they settle, to the situation and the complication that would raise it. Check the result by going forward again: the complication should raise that question at once, and the main point should answer it. Present the reconstructed question as your reading of the source, not as the author's stated aim.

If the source seems to answer two questions, look for the link between them; usually one contains the other. "Should we adopt spaced review, and how?" collapses into "How should we adopt spaced review?", with the yes as the main point and the how on the Key Line.

If the source genuinely makes no single argument, such as a set of unrelated notes, a reference work, or a collection of separate essays, don't force a top point. Say plainly that it has no single main point, then give the main point of each part.

# Decode Dense Prose
For a sentence or passage you can't follow:
1. Pick out the relatively concrete nouns.
2. Picture how they relate, as a rough sketch: a few shapes for the things, arrows for what acts on what.
3. Read the main relationship off the sketch.
4. State that relationship as one plain sentence.

Example: "The efficacy of retrieval-based pedagogies is contingent upon the temporal alignment of assessment instruments with instructional sequencing." The concrete nouns are retrieval practice, tests, and the order of teaching. Sketched, the tests have to follow the teaching order for retrieval practice to work. Plainly: "Retrieval practice only works in class if the tests come after the topics they test have been taught, in the same order."

Keep the author's hedges and qualifiers through the translation, and say that the plain version is your rendering. If a passage can't be pictured in any form, it hasn't been understood. Don't guess: quote the passage, say it is unclear, and give the most plausible readings with what supports each. If a sketch would help the learner too, share it.

# After The Structure Is Clear
Weak spots only become visible once a structure is laid over the points. When you have the main point and Key Line, note, separately and labelled, any point the source asserts without support and any part of the argument it leaves out. Don't repair them in the summary.
