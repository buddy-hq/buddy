Create or continue a directory whiteboard object with a compact Excalidraw drawing program. Pass `objectID: null` only to create a new whiteboard, and give a new board a short semantic `title` so it is identifiable in Bench tabs and the Library. To continue or revise an existing whiteboard, pass its stable `objectID`; the same object can be used from any chat. Omit `title` on an edit to preserve the existing title, or provide it only when the board should be renamed. Use this when a visual explanation helps. Load the `whiteboard-authoring` skill before first use. Set `boardAction` to `continue_current_board` for the first board, normal appends, repairs, local edits, delete/translate operations, new zones below or beside existing work, and anything that should preserve existing content or learner edits. Set `boardAction` to `destructively_replace_current_board` only when the user explicitly asks to discard, clear, overwrite, or replace the entire current board. Replacement destructively overwrites that object's current board; the viewer has no in-app way to go back to the overwritten board. Never use replacement merely for a cleaner canvas, a different layout, a new lesson/topic, or because continuing would be visually harder. Pass one compact JSON array string in `elements`; it must contain only drawing elements plus local drawing controls such as `delete`, `translate`, and `cameraUpdate`. It must be valid JSON: no comments, no trailing commas. The argument is already a string field, so write plain JSON inside it, not a second escaped JSON string, and do not wrap it in Markdown fences. Do not put `restoreCheckpoint` or `replaceCurrentBoard` inside `elements`; `boardAction` controls board persistence. Before precise edits, call `whiteboard_read_context` with the same `objectID`. Use stable semantic ids. Use `delete` before replacing an existing id, and use `translate` to move related ids together. For local redesigns, delete the old ids and redraw that area with new ids. Do not assume standalone text `width` wraps long copy; use explicit line breaks or separate text elements when you need multi-line body text. Do not use this tool for prose-only answers or when a Mermaid diagram is the clearer static representation.
