Create or continue the session whiteboard using a compact Excalidraw drawing program. Use this when a visual explanation, spatial relationship, annotated process, concept map, or evolving diagram will help the learner. Load the `whiteboard-authoring` skill before first use. Pass a compact JSON array string in `elements`. Omit `restoreCheckpoint` to create a fresh scene. To edit an existing scene, first call `whiteboard_read_context`, then begin the program with `{"type":"restoreCheckpoint","id":"<continuation handle>"}` so learner edits are preserved. Use stable semantic element ids. Use `delete` before adding a replacement with an existing id; `{"type":"delete","ids":"a,b"}` and `{"type":"delete","id":"a"}` are both accepted. Use `{"type":"update","id":"a","x":760,"y":260}` for patch-style edits and `{"type":"translate","ids":"a,b","dx":180,"dy":0}` to move related elements together. When the tool reports isolated hard collisions, make at most one roomy relayout call: begin with `restoreCheckpoint`, add `{"type":"layoutCleanup","strategy":"spread_zone"}`, and create space before local fixes. When it requests `redraw_crowded_zone_once_before_reply`, begin with `restoreCheckpoint`, add `{"type":"layoutCleanup","strategy":"redraw_zone","zoneId":"<layoutWarnings.redrawZone.id>"}`, delete exactly `layoutWarnings.redrawZone.ids`, recreate only that zone and its children with new ids in a substantially larger area, and leave every outside element unchanged. Do not use this tool for prose-only answers or when a Mermaid diagram is the clearer static representation.
