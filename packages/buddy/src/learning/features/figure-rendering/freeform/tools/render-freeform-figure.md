Render a finished, static vector figure inline in the chat from a complete SVG document in `source`, including its `<svg>` root. Choose this when position carries meaning and the picture is read once as part of your reply: a custom spatial layout, a labeled apparatus or anatomy-style drawing, a cross-section, a physical setup, or any composition where sizes, distances, containment, or arrangement are part of the idea.

Use `render_figure` for supported constrained geometry, `python_calculator` for computed function graphs and data plots, and `render_mermaid` when only connections, order, or hierarchy matter. Use the whiteboard when the picture should be built up step by step while you explain it, extended across turns, or annotated with the user, and an HTML widget when the user should manipulate something. Do not use SVG merely to restyle prose, lists, or tables.

Simplify irrelevant visual detail while preserving the spatial or causal relationship being shown. Put labels close to what they name, align corresponding parts when comparing, and make the intended reading order clear. Add realistic detail only when recognizing that appearance is itself the point. Load the `explanatory-drawing` skill before composing a new kind of figure.

Never use this tool for molecular structures, stereochemical projections (Fischer, Newman, Haworth, chair, wedge-dash), reaction schemes, coordination geometry, resonance, or electron-pushing mechanisms; load `teach-chemistry` and use native chemistry formats.

This tool checks SVG compilation and parsing; it does not verify the drawing's scientific, numerical, or geometric correctness. Compute or check exact relationships before drawing them. The chat UI displays the result automatically; continue in normal text without repeating its image URL or Markdown. The figure is saved as an object, so when the user will keep referring to it, move it onto the Bench with `bench_present` `present_object`.
