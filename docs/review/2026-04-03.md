## What "Allowed Roots" Means

Allowed roots define the directory subtrees the Buddy agent is permitted to access on the filesystem. Every HTTP request or project operation calls `isAllowedDirectory()` which uses `path.relative(root, directory)` to check whether a target falls inside any root. Paths outside all roots are rejected with a 403.

Call sites: `http/directory.ts`, `buddy-home.ts`, `open-project-registry.ts`, `project-operations.ts`, `routes/e2e.ts`.

## Recent Diff in `directory.ts`

1. **Added `resolveBuddyHomeDirectory()` to default allowed roots** — adds `os.homedir()` as an allowed root by default
2. **Added wildcard `"*"` support** — `BUDDY_ALLOWED_DIRECTORY_ROOTS="*"` bypasses the sandbox entirely

## Key Finding: `resolveBuddyHomeDirectory()` Returns the Entire Home Directory

The function name suggests a Buddy-specific path, but it returns `os.homedir()` — the full user home (e.g. `/Users/prashant` or `C:\Users\prashant`). This means adding it to allowed roots makes **every path under the home directory** accessible by default. The actual `.buddy` config dir is `resolveDefaultBuddyGlobalConfigDir()` (`~/.buddy`) and the notebook home is `~/Documents/Buddy`.

## Conceptual Overlap: Notebooks vs Projects

- **Project** (OpenCode concept): any directory with a `worktree`. Stored in SQLite `project` table with fields: `id`, `worktree`, `vcs`, `name`, `icon_url`, `icon_color`, `sandboxes`, `commands`.
- **Notebook** (Buddy concept): a managed project that lives under Buddy Home (`~/Documents/Buddy/<name>/`). Created via `createManagedNotebook` which validates the name, creates the folder, then registers it as an open project.

## Data Duplication: `desktop-notebooks.json`

Buddy maintains a separate JSON file (`~/.local/state/buddy/desktop-notebooks.json`) storing an ordered list of open project directories. OpenCode's SQLite DB already has a `project` table tracking all projects. The JSON file adds:

1. **Which projects are "open"** — the DB tracks all ever-opened projects
2. **Display order** — the DB has no ordering

This is redundant — both could be columns in the `project` table (`is_open`, `sort_order`).

## Naming Inconsistency

The codebase conflates "notebook" and "project":

- `desktop-notebooks.json` — uses "notebook"
- `openProjectRegistryEntry` / `setOpenProjectRegistryEntries` — uses "project"
- `createManagedNotebook` — creates a notebook, registers it as a project
- The JSON file stores both managed notebooks and arbitrary open projects in one list

## Storage Path Patterns

| Concern    | OpenCode                          | Buddy                          |
|------------|-----------------------------------|-------------------------------|
| Data       | `~/.local/share/opencode/`        | `~/.local/share/buddy/`       |
| Config     | `~/.config/opencode/`             | `~/.buddy/` (overridden)      |
| State      | `~/.local/state/opencode/`        | `~/.local/state/buddy/`       |
| Cache      | `~/.cache/opencode/`              | `~/.cache/buddy/`             |
| DB         | `~/.local/share/opencode/opencode.db` | N/A (uses OpenCode's DB)   |

Both use XDG paths. Buddy overrides config to `~/.buddy`. The `desktop-notebooks.json` lives in state, consistent with OpenCode's pattern (e.g. `model.json` in `Global.Path.state`).

## `/tmp` in Allowed Roots

`directory.ts:47` hardcodes `"/tmp"` as an allowed root. On macOS/Linux this is fine. On Windows it's dead code — `os.tmpdir()` returns the actual temp path and `/tmp` never matches anything. Not a bug, just unnecessary on Windows.

## Open Questions

1. Should the entire home directory be an allowed root by default? The current change does this via `resolveBuddyHomeDirectory()`.
2. Should `desktop-notebooks.json` be consolidated into OpenCode's SQLite `project` table with `is_open` and `sort_order` columns?
3. Should "notebook" vs "project" terminology be cleaned up to be consistent?
